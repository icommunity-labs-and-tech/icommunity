- Unknown routes (NotFound) redirect to the same path on noticias.icommunity.io, where the old WordPress content lives; trailing-slash variants retry the internal route first. Why: avoids hundreds of Google "soft 404" errors from legacy URLs.
- Lead forms check for a corporate email with a free-webmail domain list duplicated in `supabase/functions/_shared/freeEmail.ts` (server, source of truth) and `src/lib/corporateEmail.ts` (client). Why: the server enforces the rule, the client copy only gives instant feedback.
- Organization and WebSite JSON-LD live statically in `index.html` with stable `@id`s; per-page schemas (WebPage, Article, Product list, BreadcrumbList) are passed to `PageSEO` via `jsonLd` using builders in `src/lib/structuredData.ts` and reference the organization by `@id`. Why: one source per entity, no duplicated Organization nodes.
- Canonical origin is `https://icommunity.io` (apex, no www), defined once in `src/seo/site.ts` (`SITE_URL`). Why: www redirects to the apex and Search Console records traffic there; canonicals/sitemap pointing to www were sending a redirecting canonical.
- `src/seo/site.ts` also holds static route metadata (`STATIC_ROUTES`) and `LEGACY_INTERNAL_REDIRECTS` (old WordPress URLs whose topic was rebuilt here). When adding a page, add it to `STATIC_ROUTES` so it enters the sitemap and the prerender.
- `scripts/seo-prerender.ts` (Vite plugin, build only) writes `dist/<route>/index.html` with per-route head and crawlable body text, full article text for `/recursos/*`, and redirect stubs for `scripts/legacy-paths.txt`. Why: the SPA ships an empty `#root`; non-JS crawlers (Bing, GPTBot, ClaudeBot, PerplexityBot, LinkedIn) need real HTML. Static head tags carry `data-rh="true"` so react-helmet-async replaces them on navigation.
- The blog lives at `/blog` with posts in `src/content/blogPosts.ts` (imported from noticias.icommunity.io with original dates) and their old paths mapped in `src/content/blogLegacyRedirects.ts`, spread into `LEGACY_INTERNAL_REDIRECTS`. Why: imported posts keep their SEO by redirecting old URLs to the new page; new posts are added to the same file (published via chat).
